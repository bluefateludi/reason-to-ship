# 本地状态模板

翻译并改编自 VibeWise；见[来源与 MIT 许可](THIRD_PARTY_NOTICES.md)。同意保存后，按[状态规范](state-schema.zh-CN.md)在项目 `.reason-to-ship/` 创建这三份记录。方括号替换为实际证据或“未说明”。顶部两条英文状态行保持纯文本，供恢复 Hook 读取。不要用空模板覆盖已有记录。

```markdown

学习范围：[整个系统 / 当前涉及部分 / 混合]

## 经验

技术栈熟悉度：[各技术的经验，如已提供；否则未说明]

## 目标

能力提升目标：[可选回答]

## 偏好
检查点频率：标准
提问方式：开放式

## 已展示较好理解的概念

尚无记录。

尚无记录。
```

## learning-log.md

```markdown
# 学习进展

尚未记录学习事件。
```

实际观察的证据条目记录已知来源任务与日期、具体展示的推理、是否使用提示、仍不确定的内容。自述经验在 learner.md 中标明来源。复用旧条目前检查重置界限；项目重置后保留的历史学习不能重新授权旧方案。

按主题添加二级标题，简要记录“已介绍”“已展示理解”“需要加强”。保存推理证据，不保存聊天全文。产品偏好说明需求，不证明工程理解；用户自己的推理与 AI 讲解分开记录。合并重复内容，让每个主题可以独立读取。

等待决策时，另设标题恰为 `## Pending decision` 的独立章节，记录方案、决策名称以及在等待推理、方案确认还是实施授权。解决后将结果按选定或已实现写入项目上下文，明确 AI 提议的补充，将推理证据记入主题，再移除待确认章节。不要把待确认文字直接藏进主题。确认过的选择不等于已经实现，拟修改范围始终明确。

确认仅覆盖呈现过的方案，不补入用户没说过的字段、行为、否决选项或理由；未决项标为未知，AI 建议标为提议，不归因给用户。
